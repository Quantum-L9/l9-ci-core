# Component Manifest

## Identity

- Artifact: `l9-ci-core Makefile Component`
- Version: `4.1`
- Beneficiary: `Quantum-L9/l9-ci-core`
- Baseline: continuation v3 plus the three-repository donor harvest
- Mutation authorization: none

## Execution map

```text
Makefile
  -> python -m tools.l9_repo --workspace <root> <command>
      -> strict config/runtime validation
      -> change-policy selection and companion proof
      -> Core-owned command matrices
      -> evidence reports
      -> guarded Git mutation only for push/pr/reconcile/clean
```

## Core files

- `.l9/repo-workflow.json`: strict desired state and Core-specific policy.
- `.l9/repo-workflow.schema.json`: closed schema.
- `tools/l9_repo/__main__.py`: command engine and Git orchestration.
- `tools/l9_repo/change_policy.py`: change-context, gate-selection, and companion engine.
- `tools/l9_repo/contract_wiring.py`: exact authority-to-agent discoverability proof.
- `tools/l9_repo/reporting.py`: deterministic JSON/Markdown evidence.
- `tools/l9_repo/locking.py`: PID-aware single-flight lock.
- `tools/l9_repo/push_preflight.py`: mutation preflight.
- `tools/l9_repo/Makefile.template`: canonical facade.
- `Makefile`: generated byte-identical facade.

## Validation map

- `tests/tools/test_l9_repo.py`: configuration, orchestration, safety, status, push, locking, and agent-check tests.
- `tests/tools/test_l9_repo_change_policy.py`: change policy, exact companion rules, contract wiring, and reporting tests.
- `VALIDATION.md`: executed checks and blocked target-checkout checks.
- `validation_report.yaml`: machine-readable decision.
- `validation_checks.jsonl`: check ledger.
- `validation_findings.jsonl`: resolved and remaining findings.

## Exclusions

The component does not duplicate Core workflows, actions, complete tests, `requirements-ci.txt`, `uv.lock`, `.l9/ownership.yaml`, or SDK semantics. Those remain target-repository authorities.
